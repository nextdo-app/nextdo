# 键盘导航与手势操作

本文说明 Nextdo **实际支持**的键盘与手势操作，以及它们在哪些界面生效。对应 GitHub issue #17。

## 电脑端：键盘导航

范围：**收集箱的澄清向导**（`components/clarify-wizard.tsx`）——从收件箱点开一条待澄清事项后
走的那串问答，是最重复的一段操作，所以键盘支持优先落在这里。

进入向导后，键盘焦点会自动落在当前问题的**第一个选项**上。

| 按键 | 作用 |
| --- | --- |
| `↓` / `→` | 选中下一个选项（在末尾会绕回第一个） |
| `↑` / `←` | 选中上一个选项（在开头会绕到最后一个） |
| `Home` / `End` | 直接跳到第一个 / 最后一个选项 |
| `Enter` / `Space` | 确认当前选中的选项，进入下一个问题 |
| `Tab` | 照常在页面可聚焦元素之间移动 |

几个刻意的设计选择：

- **选中态由一个可见的焦点环表示**（accent 描边，明暗主题下都可辨识）。选项本身**不进入
  Tab 序列**，只有包裹它们的那个容器可聚焦——所以 `Tab` 的行为和改动前完全一样，
  不存在"焦点陷阱"，键盘也不会被卡在选项列表里出不来。
- **回答完一个问题后，选中态回到新问题的第一个选项，焦点也交回给新问题**，
  不需要用户重新 Tab 一遍。
- **「← 上一步」不在选项列表里**，上下键永远选不中它，它只能用鼠标点。这是有意的：
  返回不是一个"答案"，误触 Enter 退回去比多点一次鼠标更糟。
- 鼠标和触控的行为完全不受影响。

> 出处：`apps/mobile/hooks/use-option-keyboard-nav.ts`

## 手机端：滑动操作

范围：**今日页的执行池列表**（`app/(tabs)/now.tsx` 的行动行）。

| 手势 | 作用 |
| --- | --- |
| 在行动行上向右滑动 | **完成**该行动（滑过阈值即生效，行会弹回原位） |

刻意做的冲突规避——手势如果抢走页面滚动或系统返回手势，比没有手势更糟：

- **只认明显的横向意图**：手指横向位移超过 12pt、且明显大于纵向位移时，才从父级
  `ScrollView` 手里接管这次触摸。在此之前触摸始终属于滚动列表，**纵向滚动不会被抢走**。
- **不从屏幕左边缘起手**：起点在左边缘 24pt 以内的触摸完全不参与，**iOS 的系统返回手势
  照常可用**。
- **不够阈值就弹回**：松手时位移不足（且不是一次快速甩动）只会把行动弹回原位，不触发任何
  写入。滑动过程中行下方会露出「✓ 完成」的提示，让用户知道松手会发生什么。

滑动只是**加速手段**：每一行都有一个等价的「完成」按钮，两条路径调用的是同一个动作。
