# #44 澄清流程：先确认项目归属，再选择项目类型

## Goal

https://github.com/nextdo-app/nextdo/issues/44 —— 先问是否属于某个项目，再问新建/已有，选项等权、中性中文文案、按决策顺序逐步展示

## Requirements

- **R1 第一步问归属**：可行动（q1）之后的第一问改为「这件事属于某个项目吗？」，两个选项：`属于某个项目` / `不属于项目`。删除现行 q2 的「需要多个步骤才能完成吗？」。
- **R2 选了「属于」才问类型**：第二问「新建项目，还是加到已有项目？」两个选项：`新建项目` / `添加到已有项目`。
  - `新建项目` → 项目表单（项目 + 首个行动，原子创建），与现行 `multipleSteps=true` 的结果一致；
  - `添加到已有项目` → 新增一步「加到哪个项目？」（项目列表单选），选中后进行动表单并挂接（价值默认跟随项目，仍可改）。
- **R3 「不属于项目」直达**：选「不属于项目」直接进入现行 q3（约 2 分钟内能完成吗？）→ q4 → q5 的常规链，不再经过 q2b；常规链语义不变。
- **R4 视觉等权**：同一问题的两个选项样式完全一致（同组件、同 variant/size，无推荐配色、无徽标）；并取消**默认高亮** —— 键盘焦点环在用户第一次按方向键之前不出现（`use-option-keyboard-nav` 由「进入即涂第一项」改为「首次键盘交互后显示」）。
- **R5 措辞中性**：新增/改写的问题与选项用清晰、中性的中文，不出现「拆成项目」「任务层级」等术语。
- **R6 再澄清同构**：re-clarify 仍从归属问题进入；「不属于项目」= 显式不挂项目（detach，沿用 `projectId: null`）；项目列表保留「当前」标记。
- **R7 结果集合不变**：同样的用户意图得到与今天完全相同的 outcome（`project` / `next-action·project-attach` / 常规链）；变化只在提问顺序、措辞与答复字段命名。

## Non-goals

- 不新增 outcome、不改 `ClarifyOutcome` 类型。
- 不改 q3/q3b/q4/q5 的问题与语义。
- 不引入手输字段/新控件。
- 不做「空项目列表时自动改问新建」这类隐式优化 —— 空态给明确说明即可。

## Acceptance Criteria

- [ ] AC-1 归属问题：可行动项的第一问为「这件事属于某个项目吗？」；两个选项视觉等权，进入该问题时没有任何选项带强调边框。
- [ ] AC-2 类型问题仅在「属于」后出现：选「新建项目」进项目表单；选「添加到已有项目」出现项目列表（单选），选中后进行动表单且挂接该项目。
- [ ] AC-3 「不属于项目」路径：直接进入「大约 2 分钟内能完成吗？」，走完常规链；提交的 outcome 与旧的「单步 + 不属于项目」一致。
- [ ] AC-4 再澄清：从归属问题进入；「不属于项目」能解除旧挂接（替换行无 project）；选同一项目再次保存幂等。
- [ ] AC-5 决策摘要卡（GTD 决策摘要）按新问题链渲染：已回答的显示新文案，未经过的不显示。
- [ ] AC-6 门禁与证据：`pnpm lint` / `pnpm typecheck` / `pnpm test` 全绿；`.verify/clarify-project-first/` 的交互态截图与 `evidence.md` 覆盖 AC-1/2/3。
