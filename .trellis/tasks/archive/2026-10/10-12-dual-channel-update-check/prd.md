# PRD: 手机端检查更新支持正式版与测试版双渠道 (fixes #18)

## 1. 背景与问题
当前手机端/应用内的「检查更新」只能检查正式版，或者仅按当前单一渠道检查，无法让想要参与尝鲜或跟进测试版的用户在应用内发现并选择测试版本。同时，普通正式版用户也不应被无故误导升级到不稳定的测试版本。

## 2. 核心需求
1. **双渠道并发检查**：
   - 检查更新时，同时检索 GitHub Releases（通过加速代理请求 Atom Feed，降级 releases/latest）中正式版（stable）与测试版（beta/prerelease）的最新版本信息。
   - 解析各版本的关键元数据：版本号（version/tag）、发布渠道（channel: stable / beta）、发布时间（publishedAt）。
2. **多版本自主选择**：
   - 当检测到新版本时，按当前运行版本计算升级差量：
     - 若同时有正式版与测试版新版本，在界面上清晰并列呈现两个版本的卡片/切换项，展示版本号、渠道徽章、发布日期，允许用户自由点选目标版本进行下载/更新。
     - 若仅其中一个渠道有新版本，突出展示可用新版本及所属渠道。
3. **渠道偏好设置与记忆**：
   - 允许用户在设置中配置默认更新渠道（正式版 / 测试版）。
   - 默认值策略：
     - 当前正在运行测试版（带预发布后缀如 -beta）的用户，默认偏好为测试版；
     - 当前正在运行正式版的用户，默认偏好为正式版（避免误导普通用户）。
   - 偏好持久化保存，下次启动或检查时自动生效。
4. **全平台适配与下载保障**：
   - 保持所有外部下载链接全部附带 `UPDATE_PROXY_PREFIX` 加速代理前缀。
   - 移动端（Android APK 自动匹配、iOS 指引 Release 详情）、桌面端（Tauri 应用内直接下载与自动打开）、Web 端均保持一致的友好体验。

## 3. 验收标准
- [x] 正式版与测试版信息均能被准确解析，包括版本号与发布时间。
- [x] 提供更新渠道偏好切换（正式版 / 测试版），并本地持久化。
- [x] 两个渠道均有新版本时，UI 列出各版本信息，用户可自由切换选择。
- [x] 单元测试全覆盖：URL 加速代理规则、Atom Feed 丰富解析、渠道偏好存储与逻辑比较。
- [x] `pnpm verify:web` 全绿，浏览器实测与截图确认。
